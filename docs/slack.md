# Slack integration

Mention the bot with an email/user ID and period, for example:

`@Account Statements generate a statement for sample@example.com for January 2026`

The bot acknowledges in the originating thread, calls `statement.generate-from-text`, and uploads the PDF to the same thread. The account identifier is extracted locally and masked before the date request reaches OpenRouter. SQL, PDF generation, and optional S3 storage remain shared with the website adapter. Duplicate Slack event deliveries share a global Trigger.dev idempotency key for 24 hours.

## 1. Deploy and locate the hosted webhook

The `account-statement-slack` endpoint is declared in `src/trigger/slack-webhook.ts`. Deploy this repository to your Trigger.dev Test project. In the appropriate environment, open **Webhooks**, select `account-statement-slack`, and copy its hosted URL. Trigger.dev verifies signatures, handles Slack's URL challenge, and deduplicates deliveries. No separate server is needed for Slack.

## 2. Configure the Slack app

Create or update your app at https://api.slack.com/apps. Add bot scopes `app_mentions:read`, `chat:write`, and `files:write`, then install or reinstall it. Set the Slack app's **Signing Secret** on the Trigger.dev webhook endpoint using **Set signing secret** before attempting Slack URL verification.

Under **Event Subscriptions**, enable events, paste the Trigger.dev webhook URL as the Request URL, and subscribe to the `app_mention` bot event. Slack verifies the URL automatically; retry verification after setting the signing secret if necessary. Invite the app to your test channel.

## 3. Configure the Trigger.dev worker

Set `SLACK_BOT_TOKEN` (the app's Bot User OAuth Token), `SLACK_TEAM_ID`, and optionally comma-separated `SLACK_ALLOWED_CHANNEL_IDS` and `SLACK_ALLOWED_USER_IDS` in the Test project's matching environment. Empty access lists allow mentions by users in channels within the configured workspace. For initial testing, set a dedicated test channel and your user ID.

Also configure the database, Browserless, and `OPENROUTER_API_KEY` settings. `OPENROUTER_MODEL` and `STATEMENTS_BUCKET` are optional. Without S3, the PDF is uploaded from generated bytes. With S3, the worker needs GetObject as well as PutObject. Set the webhook signing secret on the endpoint, not as an environment variable.

## 4. Run a live test

Use a real test account email or supported user ID (19–26 alphanumeric characters) and a short date range. Mention the bot once in the configured channel. Check `statement.slack` and its child `statement.generate-from-text` in Trigger.dev. Expect an acknowledgment followed by the PDF in the same thread. Confirm missing accounts and empty periods return readable messages.

Statements are shared with everyone who can read that channel/thread, matching the original n8n workflow. Slack keeps uploaded files according to workspace retention, even when S3 is disabled. Use an appropriate private test channel.

The parent Slack task has one attempt so an uncertain successful upload is not automatically duplicated. Generation retains its own operational retries. On delivery failure inspect the run before manually retrying; a manual rerun can create another message/file. Trigger.dev verifies and records deliveries before acknowledging them; the webhook subscriber and Slack delivery task each have one attempt to reduce duplicate messages when delivery outcomes are uncertain.

Conversation history, interactive account confirmation, CSV, and ambiguous-account selection buttons are not implemented. An ambiguous account asks for a unique user ID; date clarification asks for a new complete mention. Nothing has been live-tested merely by deploying the task.
